## Directory Layout

KitePy separates shared training infrastructure (`kitepy/core`) from domain-specific model builders and data pipelines (`kitepy/pillars`):

```text
kitepy/
├── __init__.py               # Public exports & __version__
├── cli.py                    # `kitepy` CLI (doctor, models, datasets, train, predict, export, serve)
├── core/
│   ├── adapters.py           # TaskAdapter contract, 10 task adapters, CustomStepAdapter, Pillar Registry
│   ├── base.py               # BaseModel (shared lifecycle) & compare()
│   ├── callbacks.py          # EarlyStopping, ModelCheckpoint, CSV/WB/TB loggers, LambdaCallback
│   ├── config.py             # BaseConfig, TrainingConfig, DataConfig, 8 model configs, ExperimentConfig
│   ├── engine.py             # Universal Engine, FocalLoss, create_loss_function, MixUp/CutMix
│   ├── logging.py            # Rank-aware structured JSONL & console logger
│   ├── lr_finder.py          # LRFinder range test & LR suggestion
│   ├── metrics.py            # MetricTracker, accuracy, precision_recall_f1
│   ├── planner.py            # ExecutionPlanner, ExecutionPlan, RuntimeGuard, _SingletonBatchNormGuard
│   ├── presets.py            # Model & dataset preset registries (list_models, register_preset, ...)
│   ├── serialization.py      # Atomic writes, pickle-free .safetensors bundles, lineage metadata
│   └── utils.py              # Device helpers, freeze/block helpers, parameter groups, ModelEMA, checkpoints
└── pillars/
    ├── vision/               # CNN, Transformer, Vision (SimpleUNet, TinyDetector, timm, HF wrappers)
    ├── language/             # LLM, TextClassifier, TinyGPT, LoRALinear, chat/JSONL/streaming data
    ├── multimodal/           # VLM, DualEncoderCLIP, image-text manifest loader
    ├── audio/                # Audio, AudioCNN, AudioTransformer, log-STFT waveform pipeline
    ├── tabular/              # Tabular, TabularResNet, TabularMLP, CSV preprocessing pipeline
    └── generative/           # Generative, ConvVAE, SimpleDDPM, generative data loader
```

## Execution Lifecycle (`BaseModel.train()`)

When you call `model.train(data, ...)`:

1. **Config Partitioning & Merging**: `split_kwargs()` divides kwargs across the pillar's `default_config_class`, `DataConfig`, and `TrainingConfig`. `merge_configs()` merges `default -> preset -> user_config -> kwargs`, and `validate_config()` checks constraints (`epochs`, `batch_size`, `gradient_accumulation_steps`, `lr`).
2. **Data Resolution & Auto-Alignment**: `BaseModel._resolve_data()` accepts a DataLoader tuple, single `DataLoader`, PyTorch `Dataset`, `"synthetic"`, preset string, or local file/folder path (delegated through the Pillar Registry via `register_pillar()`). Extracted metadata (`num_classes`, `class_names`, `in_channels`, `input_dim`) updates unpinned config fields before model construction via `_auto_align_model_to_data()`.
3. **Lazy Model Build & Modifications**: If `self.model is None`, `self._build_model()` constructs the PyTorch module, optionally freezes the backbone (`freeze_backbone=True`), enables gradient checkpointing if requested, and moves the model to `device`.
4. **Pre-Flight Planning (`ExecutionPlanner`)**: When `auto_plan=True` or `memory_budget_mb` is set, `ExecutionPlanner.plan()` measures static memory and probes 1-sample activation memory (under `_SingletonBatchNormGuard`), solving for `micro_batch_size`, `gradient_accumulation_steps`, `amp_dtype`, and `gradient_checkpointing`.
5. **Universal Training Loop (`Engine`)**: `Engine.train()` runs epochs with mixed precision (`bf16`/`fp16` `GradScaler`), gradient accumulation, runtime OOM splitting and NaN/Inf recovery (`RuntimeGuard`), `TaskAdapter` batch forward/loss/metrics, callbacks, scheduler stepping, EMA shadow weight tracking (`ModelEMA`), and checkpoint saving.
6. **State Update & Execution Report**: Copies final EMA shadow weights onto `self.model` (if `ema=True`), appends epoch history to `self.training_history`, sets `self.is_trained = True`, and populates `self.execution_report` with `lineage`, `execution_plan`, `recovery`, `epochs_completed`, `global_step`, and `best_val_loss`.
