## Progressive Disclosure

KitePy is designed around four layers of control on top of the exact same `Engine` and PyTorch modules — you never outgrow the simple API and rewrite your codebase:

### Layer 1 — One-Line Defaults

```python
from kitepy import CNN

CNN("resnet18").train("cifar10")
```

Defaults (`epochs=10`, `batch_size=32`, `optimizer="adamw"`, `scheduler="cosine"`, `mixed_precision=True`, automatic train/val split, automatic GPU/MPS/CPU detection) handle the boilerplate.

### Layer 2 — Flat Keyword Overrides

Override any model, data, or training setting inline. `split_kwargs()` routes each keyword automatically to the matching dataclass and raises a typo hint if an unknown key is passed:

```python
model = CNN("resnet50", pretrained=True, num_classes=100)
model.train("cifar100", epochs=30, batch_size=64, lr=3e-4, ema=True, mixup_alpha=0.2)
```

### Layer 3 — Typed Configs & YAML Files

Lock down reproducible experiments using `ExperimentConfig`, `CNNConfig`, `LLMConfig`, `TrainingConfig`, `DataConfig`, or YAML/JSON config files:

```python
from kitepy import CNN, CNNConfig, TrainingConfig, ExperimentConfig

exp = ExperimentConfig(
    model=CNNConfig(arch="resnet", depth=50, num_classes=100, pretrained=True),
    training=TrainingConfig(epochs=50, batch_size=64, auto_plan=True, ema=True),
)
model = CNN("resnet50", config=exp).train("cifar100")
```

### Layer 4 — Custom Steps, Custom Modules & Escape Hatch

Plug in any `torch.nn.Module`, write a custom `train_step(engine, batch)` hook, implement a `TaskAdapter`, or unwrap to raw PyTorch:

```python
import torch.nn as nn
import torch.nn.functional as F
from kitepy import CNN

def custom_step(engine, batch):
    x, y = batch
    logits = engine.model(x)
    return F.cross_entropy(logits, y, label_smoothing=0.1), logits, y

net = nn.Sequential(nn.Flatten(), nn.Linear(3 * 32 * 32, 10))
model = CNN(net).train("synthetic", img_size=32, train_step=custom_step, epochs=2)

raw_module = model.unwrap()
```
