## Layered Priority Order

Configurations are merged from lowest to highest priority via `merge_configs()`:

```text
Default Dataclass  →  Model Preset  →  User Config (dict/Config/YAML)  →  Inline kwargs
     (lowest)                                                             (highest)
```

<Note>
Task defaults on multi-task classes (`Vision(task="binary" | "regression" | "segmentation")`, `Tabular(task="regression")`) apply default `num_classes` only if `"num_classes"` was not explicitly set by `config` or `kwargs`, ensuring `.load()` and explicit configs preserve custom class counts.
</Note>

## Automatic Keyword Routing (`split_kwargs`)

In constructors (`CNN(...)`, `LLM(...)`, etc.) and `.train(...)` calls, flat keyword arguments are partitioned automatically across three configs:

- **Model config** (e.g., `CNNConfig`, `TransformerConfig`, `LLMConfig`, `AudioConfig`, ...)
- **`DataConfig`** (`img_size`, `augmentation`, `val_split`, `max_length`, `streaming`, ...)
- **`TrainingConfig`** (`epochs`, `batch_size`, `lr`, `ema`, `auto_plan`, ...)

Passing an unrecognized keyword raises a `ValueError` listing the unknown key(s). If a parameter exists on multiple configs (such as `dropout` on both model config and `TrainingConfig`), `split_kwargs()` routes it to each matching config.

## Strict Typo Detection

Calling `.from_dict(..., strict=True)` (the default) or `.from_yaml(..., strict=True)` checks keys with `difflib.get_close_matches()` and raises helpful hints:

```python
from kitepy import TrainingConfig

TrainingConfig.from_dict({"epocs": 5}, strict=True)
# ValueError: Unknown TrainingConfig parameter(s): 'epocs' (did you mean 'epochs'?)
```

Pass `strict=False` to silently ignore extra keys.

## Four Ways to Configure Models

<CodeGroup>
```python Inline kwargs
from kitepy import CNN

model = CNN("resnet50", pretrained=True, num_classes=100)
model.train("cifar100", epochs=20, batch_size=64, lr=3e-4, augmentation="randaugment")
```

```python Typed Config Objects
from kitepy import LLM, LLMConfig, TrainingConfig, DataConfig

m_cfg = LLMConfig(n_layers=6, d_model=256, n_heads=8, lora=True, context_length=256)
t_cfg = TrainingConfig(epochs=5, batch_size=16, lr=2e-4, auto_plan=True)

llm = LLM("tiny_gpt", config=m_cfg)
llm.train("chat.jsonl", **t_cfg.to_dict(), max_length=256)
```

```python ExperimentConfig Object
from kitepy import CNN, CNNConfig, DataConfig, ExperimentConfig, TrainingConfig

exp = ExperimentConfig(
    model=CNNConfig(arch="resnet", depth=50, num_classes=100, pretrained=True),
    data=DataConfig(augmentation="trivialaugment", val_split=0.15),
    training=TrainingConfig(epochs=30, batch_size=64, ema=True, mixup_alpha=0.2),
    experiment_name="cifar100_resnet50",
)
CNN("resnet50", config=exp).train("cifar100")
```

```yaml Nested YAML File
# experiment.yaml
model:
  num_classes: 100
  pretrained: true
data:
  augmentation: randaugment
  img_size: 32
training:
  epochs: 30
  batch_size: 128
  lr: 0.001
  ema: true
  csv_log_dir: ./logs
```
</CodeGroup>

Loading the YAML file shown above:

```python
from kitepy import CNN

model = CNN("resnet18", config="experiment.yaml").train("cifar100")
```

## Built-In Validation Rules (`validate_config`)

For `TrainingConfig`, `validate_config()` enforces:
- Either `epochs > 0` or `max_steps` is set (non-None)
- Integer `batch_size > 0`
- `gradient_accumulation_steps >= 1`
- Scalar `lr > 0`, and every value in a differential LR `dict` (`{"backbone": ..., "head": ...}`) is `> 0`

## Serialization Methods on Every Config

All `BaseConfig` subclasses expose:
- `to_dict() -> Dict[str, Any]`
- `to_yaml(path: str)` / `from_yaml(path: str, strict: bool = True)` (writes atomically)
- `to_json(path: str)` / `from_json(path: str, strict: bool = True)` (writes atomically)
- `field_names() -> set`

`ExperimentConfig` also supports `from_dict(config_dict, model_config_cls=None, strict=True)` and `from_yaml(path, model_config_cls=None, strict=True)`.
