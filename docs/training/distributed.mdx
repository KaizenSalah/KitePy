## Mixed Precision (`mixed_precision` & `amp_dtype`)

`Engine._configure_precision()` selects AMP precision safely across hardware:

| Setting | CUDA Behavior | CPU Behavior |
|---|---|---|
| `mixed_precision=True`, `amp_dtype="auto"` (default) | Uses `torch.bfloat16` (no `GradScaler`) if `torch.cuda.is_bf16_supported()`, else `torch.float16` + `torch.amp.GradScaler("cuda")` | Disabled (`False`) |
| `mixed_precision="bf16"` (or `amp_dtype="bf16"`) | `torch.bfloat16` autocast | CPU `bfloat16` autocast |
| `mixed_precision="fp16"` (or `amp_dtype="fp16"`) | `torch.float16` autocast + `GradScaler` | Disabled (`False`) |
| `mixed_precision=False` / `"fp32"` / `"no"` / `None` | Full float32 precision | Full float32 precision |

Under FP16 `GradScaler`, `Engine._optimizer_step()` unscales before gradient norm clipping and checks scale decrease to accurately avoid stepping `self.scheduler` or `self.ema` when `GradScaler` skips an overflowed step.

## `torch.compile` Support

Enable PyTorch 2.x graph compilation with `compile=True`:

```python
model = CNN("resnet18").train(
    "cifar10",
    epochs=5,
    compile=True,
    compile_mode="default",  # passed to torch.compile(..., mode=compile_mode)
)
```

KitePy stores an uncompiled/base reference safely, skips compilation cleanly with a warning if unavailable on the runtime, and remains reusable across consecutive `.train()` calls (even with `ema=True`).

## Multi-GPU With HuggingFace Accelerate (`use_accelerate=True`)

When `use_accelerate=True` is set in `TrainingConfig` and `accelerate` is installed:
- `Engine` creates an `accelerate.Accelerator` (with `gradient_accumulation_steps` and `mixed_precision`).
- Prepares `self.model`, `self.optimizer`, `train_loader`, `val_loader`, and `self.scheduler`.
- Uses `accelerator.backward()` and `accelerator.sync_gradients` for accumulation boundaries.
- Reduces training and validation loss, `batches_run`, and every metric counter across ranks via `_reduce_distributed_metrics()` (`accelerator.reduce(..., reduction="sum")`).
- Unwraps the model (`accelerator.unwrap_model()`) at the end of `Engine.train()` and restricts checkpoints/logging to rank 0.

```python
from kitepy import Engine, TrainingConfig

cfg = TrainingConfig(epochs=5, use_accelerate=True, batch_size=32, gradient_accumulation_steps=2)
trained_model, history = Engine(pytorch_net, cfg, modality="vision").train(train_loader, val_loader)
```

Launch multi-GPU scripts with Accelerate:

```bash
accelerate launch --multi_gpu train.py
```

<Note>
`TrainingConfig.strategy` (`"auto"`, `"ddp"`, `"fsdp"`, `"deepspeed"`) and `num_nodes` are validated configuration fields stored on `TrainingConfig`. Distributed execution in `Engine` is driven via `use_accelerate=True` and Accelerate launcher configuration.
</Note>
